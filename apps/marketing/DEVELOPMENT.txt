# DiskPond website

The DiskPond product and managed-storage launch website, built with Astro. Inspired by BlinkDisk's spacious product storytelling, using DiskPond branding, shared graphite/blue tokens, locally bundled Inter, original copy and real app screenshots.

## Run locally

From the repository root, using Node 24.15.0 (24.14.0 minimum) and pnpm 11.7.0 on PATH:

```powershell
pnpm install --frozen-lockfile
pnpm dev:site
```

Open **http://127.0.0.1:3000**. No `.env`, Go build, account service or cloud credentials are required.

```powershell
pnpm types:site
pnpm build:site
pnpm preview:site
```

Run type checking and building sequentially on Windows because Astro shares its generated caches. `pnpm smoke:site` checks the built site using the repository's Electron runtime in an isolated profile. Verification: ../../docs/verification/website.txt.

## Active source

- `site/`: pages, shared layouts/components, browser interactions and styles.
- `site/config.ts`: canonical domain, GitHub releases/download, contact addresses and integer-cent prices.
- `site/screenshots.ts`: nine real app views in Light/Dark from `docs/images/`.
- `../../locales/en/website.json`: English website copy and guide content.
- `static/`: robots.txt and optional static-host response headers.
- `dist/`: generated static website, including optimized screenshots, self-hosted fonts, sitemap, social preview and licenses.

When changing an offer, update the numeric configuration and its descriptive locale copy together. The monthly/yearly amounts and enquiry totals are calculated from `site/config.ts`.

To refresh screenshots on Windows, build the renderer/main with `pnpm --filter @blinkdisk/electron prebuild`, ensure the matching pinned core is built, then run `node scripts/capture-readme.mjs`. The capture uses disposable files, real snapshots and a demo identity. Dialog images are cropped to their rendered bounds; comparison and Activity use 80% app zoom. The site generates responsive WebP copies, matches its selected appearance, and opens each image at full capture resolution with keyboard focus return.

The existing `src/`, `public/` and Sentry files are **inactive upstream reference source**. They are not website build inputs. In particular, inherited claims, legal identities, testimonials, analytics and CloudBlink services are not DiskPond content. The private package name stays `@blinkdisk/marketing` to preserve workspace conventions; no dependencies or lockfile resolutions were changed.

## Host the website

`pnpm build:site` generates **`apps/marketing/dist`**. Upload that directory to a static host that serves directory `index.html` pages and `404.html`; the site does not require a Node server or SPA fallback. The canonical URL is `https://diskpond.com`. Set the host's domain/DNS and HTTPS configuration when deploying.

Website files are excluded from `DiskPond-Windows.exe`. Electron packages its own `build/` and desktop `frontend/`, with native resources and licenses; the desktop locale list does not include `website.json`. Release source ZIPs contain the website source, while the installed Windows check verifies the ASAR/resource boundary.

An explicit Cloudflare deployment command is available after authenticating the correct account:

```powershell
pnpm --filter @blinkdisk/marketing deploy
```

This builds and deploys the static assets as `diskpond-site` using `wrangler.jsonc`. Bind `diskpond.com` in that account's domain settings; the configuration does not assume ownership of an existing DNS zone. Deployment was not performed as part of implementation.

The site has no analytics, remote fonts or embedded third-party video. Appearance is stored only as `diskpond.site.theme` in local storage; blocked storage falls back to the system theme. Static HTML preserves core navigation/download/enquiry/FAQ flows when scripts are disabled.
